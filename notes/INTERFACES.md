# Pinned interfaces

An interface is pinned here before the gate that builds it starts. Changing one needs the developer's OK, recorded in `notes/DECISIONS.md`.

## 1. Package layout (T35; approved with changes, T38)

```
code/
  main.py                      starter entry point; becomes a thin CLI wrapper later (not in the parser gate)
  deletion_audit/              the pipeline package (renamed from ghost_audit, T38)
    __init__.py
    evidence/                  PARSER GATE (orch-builder) owns this subtree
      __init__.py              public API: parse_all, parse_file, Observation, FileParse, EvidenceIndex
      model.py                 the dataclasses below (pinned)
      manifest.py              dataset/evidence_files.csv -> FileRef(file_id, path, origin, captured_at)
      registry.py              family sniffers; dispatch needs exactly one match
      interpret.py             THE single interpretation point: RawRecord -> Observation
                               (also holds the one identifier normalizer and the one time normalizer)
      sqlsafe.py               in-memory sqlite3 loader: authorizer, step cap, row cap
      families/                one module per file family; syntax only, emits RawRecord
    inputs/                    PARSER GATE (T38): typed loaders for the three CSV inputs
      __init__.py              public API: load_activity, load_identities, load_audit_log
      model.py                 ActivityRow, IdentityRow, AuditLogRow (pinned below)
  evaluation/                  G4 (orch-eval-engineer) owns this subtree
  tests/
    evidence/                  PARSER GATE: test_<family>.py, fixtures/, raw_check.py
    inputs/                    PARSER GATE: tests for the CSV loaders
notes/parser_raw_check.md      PARSER GATE: generated by code/tests/evidence/raw_check.py (T13)
```

- Later gates add their own subpackages (`identity/`, `state/`, `policy/`, `steps/`, `model_client/`), each pinned here before its gate starts.
- Tests use the standard library's `unittest` (pytest is not installed). Run them from the repo root: `python3 -m unittest discover -s code/tests -t code`.
- Runtime dependencies: the standard library, plus `pdfplumber` (already installed) for PDF text layers.

## 2. Observation interface (`code/deletion_audit/evidence/model.py`)

```python
IdKind = Literal["email", "phone", "email_hash", "user_id", "name", "subject_reference", "other"]

@dataclass(frozen=True)
class Identifier:
    kind: IdKind
    value: str      # normalized by interpret.normalize_identifier (email: stripped, lower-case; phone: digits with a leading +)
    raw: str        # exactly as written in the file
    field: str      # source field, e.g. "lookup_key", "match_key", "email", "message_text"

@dataclass(frozen=True)
class Locator:
    file_id: str
    kind: Literal["line", "sql_row", "json_path", "pdf_page", "image"]
    ref: str        # "L42", "customer_profiles#rowid=7", "$.snapshots[3].records[0]", "p2"

@dataclass(frozen=True)
class SnapshotScope:
    file_id: str
    systems: frozenset[str]          # system_ids the snapshot declares it covers
    as_of: str | None                # the scope's own time, e.g. snapshot_scope.captured_at or the collection's captured_at
    source: Literal["sql_snapshot_scope", "full_collection"]
    collection: str | None           # table or collection name when source == "full_collection"
    locator: Locator                 # where the scope is declared

@dataclass(frozen=True)
class Observation:
    file_id: str
    family: str
    locator: Locator
    captured_at: str                 # the FILE's capture time, from the manifest
    record_time: str | None          # the RECORD's own time (line, row or snapshot time); None if the record states none
    system_id: str | None            # from the resource type, table or service, via interpret.SYSTEM_MAP
    resource_id: str | None
    record_identifiers: frozenset[Identifier]   # identifiers stored IN the record
    lookup_identifiers: frozenset[Identifier]   # keys the observing process looked up with, on the same trace_id
                                                # in the same file; never merged into record_identifiers
    trace_id: str | None
    scope: SnapshotScope | None      # the declared scope this observation was captured under, if any
    event: str | None                # event name, record_type or table, as written
    attrs: Mapping[str, str]         # state-bearing fields, raw strings; state is decided downstream, not here
    text: str | None = None          # free text (support message_text, PDF text), kept raw for later PII checks

ParseStatus = Literal["OK", "EMPTY", "UNKNOWN_FAMILY", "AMBIGUOUS_FAMILY", "ERROR", "NEEDS_MODEL"]

@dataclass(frozen=True)
class FileParse:
    file_id: str
    path: str
    family: str | None
    status: ParseStatus
    observations: tuple[Observation, ...]
    scopes: tuple[SnapshotScope, ...]   # every scope the file declares, including scopes with zero rows
    detail: str | None                  # reason or error text; never file content

    @property
    def ok(self) -> bool: ...           # True only for status == "OK"

@dataclass(frozen=True)
class EvidenceIndex:
    files: Mapping[str, FileParse]      # one entry per manifest row
    def observations(self) -> tuple[Observation, ...]: ...
    def scopes(self) -> tuple[SnapshotScope, ...]: ...
    def failures(self) -> tuple[FileParse, ...]: ...   # every FileParse that is not OK, NEEDS_MODEL included

def parse_file(ref: FileRef, dataset_dir: Path) -> FileParse: ...
def parse_all(dataset_dir: Path) -> EvidenceIndex: ...
```

## 3. CSV input loaders (`code/deletion_audit/inputs/`, T38)

```python
@dataclass(frozen=True)
class ActivityRow:      # dataset/system_activity.csv
    activity_id: str; event_time: str; event_type: str; source_system: str
    target_system: str; resource_id: str | None; reported_result: str | None; details: str

@dataclass(frozen=True)
class IdentityRow:      # dataset/user_identities.csv
    user_id: str; name: str | None; email: Identifier | None; phone: Identifier | None
    email_hash: str | None; updated_at: str

@dataclass(frozen=True)
class AuditLogRow:      # dataset/user_audit_log.csv (audit_id is kept: it can be cited)
    audit_id: str; user_id: str; event_time: str; field_name: str
    old_value: str | None; new_value: str | None
    old_identifier: Identifier | None; new_identifier: Identifier | None   # set when field_name names an identifier

def load_activity(dataset_dir: Path) -> tuple[ActivityRow, ...]: ...
def load_identities(dataset_dir: Path) -> tuple[IdentityRow, ...]: ...
def load_audit_log(dataset_dir: Path) -> tuple[AuditLogRow, ...]: ...
```

- **Times are exact-second UTC (`...Z`), never rounded** (the timing grid depends on them). They use the same time normalizer as `interpret.py`.
- **IDs are copied exactly, never composed.** Identifiers go through the one normalizer in `interpret.py`, and the raw value is kept.
- **A malformed row raises `InputFormatError`**, naming the file and line. Rows are never skipped silently. Empty fields become `None`.
- Input order is preserved.
- Linking (which rows belong to which person) is out of scope.

## 4. Contract rules (each one has a test)
1. **One `FileParse` per manifest row.** `parse_all` never raises on a bad file; it records `ERROR` with a reason. It raises only if the manifest itself is missing.
2. **`EMPTY` means a non-empty file that yields neither an observation nor a declared scope.** It is a failure (T8) and is never read as "no records".
   - A file that declares a scope (a full collection or a `snapshot_scope` table) but has no rows under it is `OK`, with that scope and zero observations under it. That is how absence gets proved (T38).
   - Required test: DEV case_31's file, `evidence_51` (`customer_data_snapshot_bundle_20260915.json`). Its `account_service` / `customer_profiles` collection has 0 records and must come back as a `full_collection` scope with no observations under it. The file status is `OK`.
   - Unknown or ambiguous families are also failures.
3. **Families are detected from content** (header lines, keys, DDL), never from the filename or the manifest `origin`. Exactly one sniffer must match.
4. **Parsers do syntax only.** They emit a `RawRecord`: the locator, the fields as raw strings, the raw record time, the trace_id and the free text. Only `interpret.py` turns a `RawRecord` into an `Observation`. It holds the one system map, the one identifier extractor and normalizer, and the one time normalizer, and it attaches scopes.
5. **Times are normalized to ISO-8601 UTC (`...Z`) and never rounded or truncated.** Seconds are kept exactly as written, because T5's ±1 s precision fixture depends on them.
6. **`system_id` comes from the resource type, table or service named in the evidence**, never from `system_activity.target_system`. G1 found that activity rows use different system names from the gold answers.
7. **`lookup_identifiers` come from the same `trace_id` in the same file**, for example `profile_lookup_started lookup_key=...` paired with `profile_lookup_completed resource_id=...`. They are kept apart from `record_identifiers`.
8. **Snapshot scopes are recorded only where a file declares completeness** (T50, T68): a SQL `snapshot_scope` row, or a snapshot-bundle entry naming its data store, even an empty one. A plain collection export (source, collection, records) declares no scope. Each observation from a declaring file gets the scope it falls under. Whether a missing row means ABSENT is decided downstream (T54), not here.
   - **PDF pages (T68):** a page gives its identifiers to every resource it names. A real-data test asserts that no page names more than one resource together with more than one person. G5 rule: identifiers on a page that names several resources or several people never link.
   - **PDF record time (T68):** the parser leaves `record_time` as None today. G5 uses the page's stated time, at its stated precision, when the page states one, otherwise the file's `captured_at`, and records which one it used. The field that carries this is pinned with G5's interface.
9. **Images return `NEEDS_MODEL`.** G7 reads them through cached model calls (T7). A PDF with no text layer also returns `NEEDS_MODEL`.
10. **Untrusted content is never executed or obeyed.** The only exception is SQL, which is loaded into an in-memory sqlite3 database:
    - its authorizer denies ATTACH, DETACH and extension loading;
    - a **step cap** (`set_progress_handler`) and a **row cap** make a hostile or huge file fail as `ERROR` instead of hanging (T38);
    - both caps have tests;
    - there is no network and no `eval`.
11. **Order is deterministic:** files in manifest order, then observations in locator order.

## 5. Out of scope for the parser gate
Linking observations or CSV rows to a person or an account, state at `audit_at`, policy, step generation and model calls. Those belong to G5 and G7.

## 6. T13 raw-file comparison (parser gate; amended by T38)
- **Unseen families:** the families that `../research/16_test_coverage.md` §3.2 marks as never a DEV primary, mapped to the registry's family names, plus any family the registry finds that the table does not name.
- **The person's identifiers** (test tooling only, not the pipeline's linking):
  1. Resolve each test request's email to its `user_id`, through current emails in `user_identities.csv` and old emails in `user_audit_log.csv`.
  2. Collect every identifier that user has had: current and old emails, and current and old phones, from both files.
- **Case selection:** for each unseen family, take the 3 test cases with the lowest `sha256(case_id)` among those whose person appears in a file of that family under **any** of those identifiers. The choice is deterministic and not hand-picked.
- **Comparison:** for each selected case, list every raw line, row or record in that file that contains any of the person's identifiers, or a resource ID on the same trace. Each must map to an observation with the same record time, resource ID, identifiers and trace_id.
- **Output:** `notes/parser_raw_check.md`, giving per-case counts of matched lines, missed lines and mismatched fields, with locators. It also states which identifier matched (current or old, email or phone).
