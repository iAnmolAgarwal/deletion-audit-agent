# Parser raw-file check (T13, INTERFACES.md section 6)

Generated by `code/tests/evidence/raw_check.py`; do not edit by hand.

- Families: the never-DEV-primary families of `research/16_test_coverage.md` section 3.2 (files picked by that table's file-name stem), plus registry families the table does not name.
- Person search: the request's `user_id`, every email and phone the user has had (current and old, from `user_identities.csv` and `user_audit_log.csv`), the sha256 of each of those emails, and the resource IDs a `system_activity.csv` row links to the `user_id` (T68).
- Cases: the 3 test cases with the lowest sha256(case_id) whose person appears in a file of the family.
- A raw unit is checked when it holds a person identifier, or carries a resource ID on the same trace as such a unit ("companion"). It must map to an observation with the same locator, record time, resource ID and trace. Identifiers are compared for equality (T68): the observation's record identifiers plus its lookups that appear in the unit must equal the unit's identifier tokens (emails, known phones, user IDs, 64-hex hashes); lookups borrowed from the trace must appear in another unit on the same trace; a companion must carry the trace's person identifier among `lookup_identifiers`.
- Identifier values are not printed; only their kind and whether they are current or old.
